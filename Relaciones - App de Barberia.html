Modelo de dominio
Aplicación de turnos de barbería

Este modelo identifica las primeras clases de la aplicación y cómo se relacionan. Como punto de partida, cada turno corresponde a un cliente, un barbero y un servicio.

2. Cuadro de relaciones

RelaciónTipoInterpretación
Cliente → TurnoUno a muchos (1:N)Un cliente puede tener cero, uno o muchos turnos. Cada turno pertenece a un solo cliente.
Barbero → TurnoUno a muchos (1:N)Un barbero puede tener cero, uno o muchos turnos. Cada turno está asignado a un solo barbero.
Servicio → TurnoUno a muchos (1:N)Un servicio puede aparecer en cero, uno o muchos turnos. Cada turno incluye un solo servicio.
Barbero → HorarioTrabajoUno a muchos (1:N), propuestaUn barbero puede tener cero, uno o muchas franjas horarias. Cada franja pertenece a un solo barbero.

3. Esquema de lectura

CLIENTE [1] ───────── [0..*] TURNO BARBERO [1] ───────── [0..*] TURNO SERVICIO [1] ───────── [0..*] TURNO BARBERO [1] ───────── [0..*] HORARIO TRABAJO (propuesto) TURNO.Estado: EstadoTurno (enum)

1 significa «exactamente uno». 0..* significa «ninguno, uno o muchos». Por ejemplo, un cliente recién registrado puede no tener turnos, pero un turno siempre debe tener un cliente.

4. EstadoTurno: opciones de estado

EstadoTurno es un enum implementado, no una entidad independiente. Define estas opciones: Pendiente, Confirmado, Cancelado, Atendido y NoAsistio. Cada turno comienza en Pendiente.

El enum define valores posibles; las reglas de cambio de estado se implementarán con la funcionalidad de reservas.

5. Horario de trabajo y reserva

HorarioTrabajo describe cuándo trabaja un barbero de forma habitual, por ejemplo, los martes de 09:00 a 13:00 y de 16:00 a 20:00. Son dos franjas, representadas por dos objetos.

Turno representa una reserva concreta, con fecha, hora, cliente, barbero y servicio. No se propone una relación directa entre Turno y HorarioTrabajo: al reservar se consultará la disponibilidad del barbero.

DayOfWeek es el enum de .NET para los días de la semana. TimeSpan representa una duración; en este diseño se usa como tiempo desde medianoche para indicar una hora del día.

6. Ejemplo

Turno 25: Juan Pérez (cliente) se atiende con Martín (barbero) para un corte de pelo (servicio), el 03/11/2026 a las 15:00.

7. Reglas previstas y alcance

Las reservas deberán respetar la jornada del barbero y la duración del servicio. No se admitirán turnos pasados ni superpuestos para el mismo barbero o cliente. Las cancelaciones conservarán el registro. Estas reglas están identificadas para el diseño; su implementación corresponde a la funcionalidad de turnos.

Este documento sigue siendo un modelo en revisión. Cliente, Barbero, Servicio, Turno y EstadoTurno están en el código. HorarioTrabajo se incorpora únicamente al diseño. No se crea una clase nueva con esta actualización.

Alcance acordado: todos los barberos realizan los mismos servicios disponibles. Por ahora no se necesita una asociación directa entre Barbero y Servicio; cada Turno identifica ambos.

El acceso de usuarios y perfiles queda pendiente para las etapas posteriores. Este borrador no representa todavía toda la arquitectura final.
